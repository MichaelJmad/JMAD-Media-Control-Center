Objectives

Preserve all existing file-and-folder operations and behaviors — renaming must retain the same capabilities the app had before.
Renaming requirements
File and folder renaming must be resilient to long, irregular, and noisy filenames.
Episode renaming must strip "fluff" (extraneous text) while reliably preserving the episode number.

Compatibility & completeness
Review earlier versions of the application and confirm no previously available functions or features have been unintentionally removed.
Carefully implement the code to match these requirements and preserve backward compatibility where relevant. Do not omit any previously supported behaviors unless they were explicitly removed.
Implementation notes (for the developer)
Make the scanner efficient and memory-conservative so it scales to large libraries.
Ensure the parser that extracts episode numbers tolerates many naming conventions and unusual characters.
Season detection should fall back gracefully (e.g., if the folder name is ambiguous, allow manual override in the preview).

Workflow
User selects a node (folder).
If it’s a subfolder → only its files will be moved (flattened).
If it’s the root → all files under it recursively will be moved (flattened).
System scans for conflicts.
Collects all candidate files.
Checks if any will collide in the target folder (same filename).
If collisions are found, show those files in red in the preview panel.
Non-conflicting files show normally.
User resolves conflicts.
Options: rename, skip, or overwrite.
Only once conflicts are resolved can the move be confirmed.
Move execution.
Move files into the target folder (flattened).
Delete empty source folders.
Undo / Redo support.
Undo: restores files to original locations, recreates deleted folders.
Redo: reapplies the flattened move, cleans up empty folders, and re-applies conflict flags.
