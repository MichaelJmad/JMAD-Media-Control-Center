<h1>JMAD Media Tool: Developers Roadmap (Version 1)</h1><h2>1. Architectural Overview &amp; Data Flow</h2><p>The JMAD Media Tool operates as a persistent, single-instance application (desktop or server-side). It must manage file system paths and persistent user settings. All workflows prioritize <strong>non-destructive, preview-first operations</strong> and <strong>atomic file handling</strong>.</p><h3>1.1 Core Application Components</h3><table><tbody><tr><th><p>Component</p></th><th><p>Responsibility</p></th><th><p>Persistent Data Storage</p></th><th><p>Technical Notes</p></th></tr><tr><td><p><strong>Directory Monitor Service</strong></p></td><td><p>Persistent, low-impact background thread. Scans <code>Staging Path</code> and <code>Watch Directory</code> for changes (polling or OS events). T riggers <strong>File Detection Workflow</strong>.</p></td><td><p>Configuration settings (Paths, Scan Interval).</p></td><td><p>Must be highly optimized to minimize CPU/IO load.</p></td></tr><tr><td><p><strong>State Manager</strong></p></td><td><p>Centralized authority for all Media Title statuses (Gray, Blue, Green, Error). Manages transitions, indexes media, and updates the UI.</p></td><td><p><strong>Media Title Index (Database/JSON):</strong> Stores source path, target path, current state, metadata ID (TMDB/TVDB), flag data, and <strong>original raw name</strong>.</p></td><td><p>Central object responsible for application state.</p></td></tr><tr><td><p><strong>Metadata Engine</strong></p></td><td><p>Handles external API calls (TMDB, TVDB) and manages the generation/reading of NFO files and artwork assets.</p></td><td><p>API Keys, Preferred Languages, Default Watch Order.</p></td><td><p>Must handle API rate limiting and return structured JSON for NFO generation. Targets media files (<code>.mkv</code>, <code>.mp4</code>) and standard image types.</p></td></tr><tr><td><p><strong>File Handler</strong></p></td><td><p>Executes all file system commands (Rename, Move, Delete, Rollback). <strong>Must ensure all moves/renames are atomic operations.</strong></p></td><td><p>Naming Templates, Fluff Regex Patterns.</p></td><td><p>Operations must be executed using <strong>Copy-Verify-Delete Original</strong> or equivalent OS-level atomic operation to ensure data fidelity.</p></td></tr><tr><td><p><strong>Appearance Profiles</strong></p></td><td><p>Manages all visual settings (Themes, Status Colors, Icons).</p></td><td><p>Saved custom profiles (JSON).</p></td><td><p>Must be a reactive component for instant theme switching.</p></td></tr></tbody></table><h3>1.2 File Detection Workflow (Directory Monitor)</h3><ol><li><p><strong>Trigger:</strong> <code>Directory Monitor Service</code> detects new/changed content in <code>Staging Path</code> or <code>Watch Directory</code>.</p></li><li><p><strong>Input Handling:</strong> If content is detected in the <code>Watch Directory</code>, the <code>File Handler</code> executes an <strong>atomic move</strong> to the <code>Staging Path</code>.</p></li><li><p><strong>Initial Scan:</strong> The <code>File Handler</code> performs a recursive scan, identifying media files and associated auxiliary files (e.g., subtitles, covers).</p></li><li><p><strong>Fluff Removal (Initial):</strong> <code>File Handler</code> applies the default <strong>Fluff Regex Patterns</strong> to the root folder name and contained files to create a <strong>Clean Name</strong>. The raw original name must be preserved in the <code>State Manager</code>.</p></li><li><p><strong>Index/State Assignment:</strong> A new entry is created in the <code>State Manager</code>.</p></li><li><p><strong>UI Update:</strong> The new Media Title is displayed in the Staging Directory UI with the <strong>Unorganized (Gray)</strong> status.</p></li></ol><h2>2. Detailed Workflow Functionality</h2><h3>3.1 Organization Dialog (Single Item Processing UI)</h3><p>The <strong>Organization Dialog</strong> is the comprehensive, three-panel interface used to complete the <strong>Ingest/Map (Gray</strong> <math-inline class="math-inline math-node" title="" contenteditable="false"><span class="math-render"><span class="katex"><span class="katex-html" aria-hidden="true"><span class="base"><span class="strut" style="height: 0.3669em;"></span><span class="mrel">→</span></span></span></span></span></math-inline> <strong>Blue)</strong> workflow for a single media item. It centralizes file review and metadata search.</p><ol><li><p><strong>Source Panel (Left):</strong> Displays the raw file/folder hierarchy. Contains controls to:</p><ul><li><p>Toggle display between <strong>Raw Name</strong> and <strong>Clean Name</strong>.</p></li><li><p>Initiate move actions to <strong>Uncategorized</strong> or <strong>Quarantine</strong> folders.</p></li></ul></li><li><p><strong>Control Panel (Center):</strong> Houses interactive elements:</p><ul><li><p><strong>Metadata Search Bar:</strong> Component used to search external APIs (TMDB/TVDB) and map the media title to a definitive external ID.</p></li><li><p><strong>Media Type Selector:</strong> Dropdown for selecting saved templates.</p></li><li><p><strong>Fluff Pattern Editor Access:</strong> Button to temporarily modify or exclude fluff patterns for the selected item.</p></li><li><p><strong>Anchoring Tool Access:</strong> Button to open the drag-and-drop anchoring interface (Section 4.2).</p></li></ul></li><li><p><strong>Target Structure Layout (Right Panel Preview):</strong> This panel displays two columns for comparison and editing:</p><ul><li><p><strong>Original Name:</strong> Shows the raw file/folder name as it exists in the Staging Directory (<strong>not the full path</strong>).</p></li><li><p><strong>New Structure (Editable):</strong> Projects the <strong>proposed final file name or directory structure</strong> based on the current <strong>Media Type</strong> and <strong>Metadata ID</strong>. This will include the appropriate prefix (e.g., <code>Season 01/S01E01</code> or just <code>Movie Title (Year)</code>). <strong>This view MUST be editable</strong> by the user for final manual adjustments before commitment.</p></li></ul></li></ol><p><strong>Commit Action (<code>processOrganizeAndRename</code>):</strong> This is a single atomic execution that commits the renaming and structure creation.</p><h4>3.1.1 Media Type Specification</h4><p>The <strong>Media Type Selector</strong> is a crucial component that allows the user to define the output format for both the directory structure and the file names based on the content type (e.g., Movie, TV Series).</p><p><strong>Template Structure:</strong>
Templates are persistent, user-editable strings stored in the <code>File Handler</code>'s persistent data. They utilize placeholders corresponding to known metadata fields (fetched by the <code>Metadata Engine</code>).</p><table><tbody><tr><th><p>Placeholder</p></th><th><p>Source Data</p></th><th><p>Example Output</p></th><th><p>Usage Context</p></th></tr><tr><td><p><code>{title}</code></p></td><td><p>Standardized Title</p></td><td><p><code>The Matrix</code></p></td><td><p>Movie and Series Root Folder</p></td></tr><tr><td><p><code>{year}</code></p></td><td><p>Release Year</p></td><td><p><code>1999</code></p></td><td><p>Movie and Series Root Folder</p></td></tr><tr><td><p><code>{quality}</code></p></td><td><p>Derived from File Name</p></td><td><p><code>1080p</code></p></td><td><p>File Naming Only</p></td></tr><tr><td><p><code>{season:00}</code></p></td><td><p>Season Number (Padded)</p></td><td><p><code>S01</code></p></td><td><p>Series Folder/File Naming</p></td></tr><tr><td><p><code>{episode:00}</code></p></td><td><p>Episode Number (Padded)</p></td><td><p><code>E05</code></p></td><td><p>Series File Naming</p></td></tr><tr><td><p><code>{ext}</code></p></td><td><p>Original File Extension</p></td><td><p><code>.mkv</code></p></td><td><p>File Naming Only</p></td></tr></tbody></table><p><strong>Default Templates (Examples):</strong></p><ul><li><p><strong>Movie Folder Template:</strong> <code>{title} ({year})</code></p><ul><li><p><em>Output:</em> <code>The Matrix (1999)/</code></p></li></ul></li><li><p><strong>Movie File Template:</strong> <code>{title} ({year}) [{quality}]{ext}</code></p><ul><li><p><em>Output:</em> <code>The Matrix (1999) [1080p].mkv</code></p></li></ul></li><li><p><strong>Series Folder Template:</strong> <code>{title}/Season {season:00}</code></p><ul><li><p><em>Output:</em> <code>The Expanse/Season 03/</code></p></li></ul></li><li><p><strong>Series Episode Template:</strong> <code>{title} - {season:00}{episode:00}{ext}</code></p><ul><li><p><em>Output:</em> <code>The Expanse - S03E05.mkv</code></p></li></ul></li></ul><p><strong>Preview Interaction:</strong>
When the user selects a <code>Metadata ID</code> and a <strong>Media Type</strong> (template), the <strong>Target Structure Layout</strong> instantly resolves the template string against the fetched metadata, populating the <strong>New Structure (Editable)</strong> column with the proposed new file/folder names, including required structural prefixes (like <code>Season 01/</code>). The user can then manually edit these names. <strong>The <code>Commit Action</code> (<code>processOrganizeAndRename</code>) MUST use the final text from the editable New Structure column to execute the renaming process.</strong></p><h3>3.2 Batch Organize Wizard (Bulk Processing)</h3><p>This wizard handles multiple selected <strong>Gray</strong> items, minimizing repetitive search and mapping actions.</p><h4>3.2.1 Series Assumption Algorithm</h4><ol><li><p><strong>Fluff Cleaning:</strong> Run deep <code>Fluff Removal</code> on all selected items.</p></li><li><p><strong>Grouping:</strong> Items are grouped by high-similarity of the <strong>Clean Name</strong>.</p></li><li><p><strong>User Confirmation Loop:</strong></p><ul><li><p><strong>Prompt 1 (Grouping):</strong> User confirms which items (e.g., files for Season 1 and files for Season 2) belong to the assumed group. Items deselected are queued for the next loop.</p></li><li><p><strong>Prompt 2 (Search/ID):</strong> User confirms the final series name and assigns the external ID.</p></li><li><p><strong>Layout Confirmation:</strong> A simplified <strong>Target Structure Layout</strong> shows the planned merged structure.</p></li><li><p><strong>Status Update:</strong> Confirmed items transition to <strong>Processing (Blue)</strong>.</p></li></ul></li></ol><h3>3.3 State-Aware Merge Logic (Critical Safety System)</h3><p>This logic prevents merging lower-state content into higher-state content without required pre-processing, ensuring structural integrity.</p><table><tbody><tr><th><p>Condition</p></th><th><p>Source State</p></th><th><p>Target State</p></th><th><p>Required Action Sequence (Pre-Processing)</p></th></tr><tr><td><p><strong>Standard Merge</strong></p></td><td><p>🔵 Blue</p></td><td><p>🟢 Green or 🔵 Blue</p></td><td><p><code>File Handler</code>: Merge (copy/move) files into target structure.</p></td></tr><tr><td><p><strong>CRITICAL Merge</strong></p></td><td><p>⚪ Gray</p></td><td><p>🟢 Green or 🔵 Blue</p></td><td><p><strong>1. Final Action:</strong> After successful transition to <strong>Blue</strong>, the merge is completed.</p></td></tr></tbody></table><h2>4. Advanced Subsystems Specification</h2><h3>4.1 Fluff Removal Engine</h3><ul><li><p><strong>Implementation:</strong> Must use a multi-stage approach: <strong>1. Default system-wide Regex</strong> (for standard tags like <code>[WEB-DL]</code>, <code>[YTS]</code>). <strong>2. User-defined Regex patterns</strong> (customizable in Settings). <strong>3. Manual override/whitelist</strong> (per-file exclusion).</p></li><li><p><strong>Validation:</strong> Regex logic must be validated to prevent accidental removal of critical identifiers (e.g., season/episode numbers, custom naming identifiers).</p></li></ul><h3>4.2 Media Title Anchoring System</h3><ul><li><p><strong>Implementation:</strong> The <code>Metadata Engine</code> fetches the full chronological/canonical watch order list (if available via API).</p></li><li><p><strong>Anchoring Data:</strong> Must rely on specific NFO tags (<code>sorttitle</code>, <code>episode</code> number) to insert movies or specials correctly into the episodic timeline.</p></li><li><p><strong>Manual Override:</strong> The <strong>Anchoring Interface</strong> must be a drag-and-drop UI that allows the user to manually adjust the order, overwriting scraped anchor data.</p></li></ul><h3>4.3 Error and Transactional Rollback</h3><p>The <strong>Console Panel</strong> displays all logging and error output. The <code>File Handler</code> must treat all structural file changes as a single transaction:</p><ol><li><p><strong>Critical Failure:</strong> If any step fails (e.g., target directory creation, file lock), the entire sequence halts.</p></li><li><p><strong>Rollback:</strong> The <code>File Handler</code> attempts to undo any successful changes made during that specific operation (e.g., deleting partially created folders, restoring original file names).</p></li><li><p><strong>Logging:</strong> Log full details to the <strong>Console Panel</strong> and set the Media Title state to <strong>Critical Error (Red)</strong>.</p></li></ol><h3>4.4 Directory Management (Safety)</h3><table><tbody><tr><th><p>Folder</p></th><th><p>Purpose</p></th><th><p>Functional Requirement</p></th></tr><tr><td><p><strong>Staging Directory</strong></p></td><td><p>Primary input/processing area.</p></td><td><p>Monitor Service runs here. All state transitions occur here.</p></td></tr><tr><td><p><strong>Uncategorized Folder</strong></p></td><td><p>User-flagged items <strong>unsure how to process</strong> (e.g., partial files).</p></td><td><p>Must <em>not</em> be monitored by the <code>Directory Monitor Service</code>. Only manual interaction allowed.</p></td></tr><tr><td><p><strong>Quarantine Folder</strong></p></td><td><p>Items marked for removal/deletion (e.g., duplicates).</p></td><td><p>Must have a dedicated <strong>Purge</strong> function (permanent delete) and a <strong>Restore</strong> function linked to the file's original path metadata.</p></td></tr><tr><td><p><strong>Watch Directory</strong></p></td><td><p>Automated input drop point (e.g., torrent client completed downloads).</p></td><td><p>Must be monitored by the <code>Directory Monitor Service</code>. All detected items are <strong>moved</strong>, not copied, to Staging.</p></td></tr></tbody></table><h3>4.5 Get List Management (V1 Foundation)</h3><p>This module provides the structural foundation for future automated acquisition features, acting as a persistent list of desired media.</p><ul><li><p><strong>Persistence:</strong> The list must be saved in the application's persistent storage.</p></li><li><p><strong>Functionality:</strong> Allows users to manually add, view, and mark as acquired, desired Movies and TV Series.</p></li><li><p><strong>Data Fields:</strong> Each entry must store at least: <code>Title</code>, <code>External ID</code> (optional), <code>Status</code> (Wanted, Acquired, Downloading), and <code>Type</code> (Movie/Series).</p></li></ul><h2>5.
